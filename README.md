# tech-support

Бот читает Telegram-чат с заказчиком и решает по каждому сообщению: это баг, который мы чиним по контракту, или доработка за рамками контракта. Заодно оценивает, сколько времени уйдёт и насколько это срочно. Стек: Python, Vercel, Supabase, OpenRouter.

Сейчас готов **классификатор**. Бот и сохранение в Supabase будут следующими шагами.

## Как устроен классификатор

Модель не отвечает одной меткой. Она проходит **анкету** (`classifier/questionnaire.py`), где на каждый вопрос есть три формата ответа: да/нет, процент или вариант A–E.

| id | формат | вопрос |
|---|---|---|
| `is_task` | да/нет | нужна ли работа команды |
| `type` | A–E | баг / доработка / вопрос / обсуждение / шум |
| `bug_probability` | % | вероятность, что это дефект |
| `coverage` | A–D | в рамках контракта (баг или оплаченная задача) / мелкая правка в рамках поддержки / выход за рамки / не задача |
| `contract_match` | A–C | относится к оплаченной задаче (paid) / к задаче «к предложению» (to_offer) / ни к одной |
| `complexity` | A–E | ≤1 ч / 1–4 ч / 1–2 дня / 3–5 дней / больше недели |
| `urgency` | A–D | критично / высокая / обычная / низкая |
| `needs_clarification` | да/нет | нужно ли что-то уточнить у заказчика |

Из ответов на анкету `aggregate.py` собирает итоговый `Verdict`: категория, входит ли задача в контракт, оценка в часах и приоритет.

Классифицирует только JEV (`typesafe/jev-router` через OpenRouter), ничего другого нет. Роутер JEV сам выбирает модель под каждый запрос: простые сообщения уходят в дешёвые flash-модели, сложные — в сильные. Ответ JEV жёстко ограничен JSON-схемой анкеты (`structured_outputs`, strict), поэтому невалидный ответ невозможен.

```
jev.py             запрос к JEV: промпт + few-shot + JSON-схема, повторы при 429/5xx
prompt.py          системный промпт, контракт, few-shot примеры
fewshot.py         подбор примеров из фикстур: самые похожие + по одному каждого типа
questionnaire.py   анкета и её JSON-схема
aggregate.py       ответы анкеты → Verdict
contract.py        загрузка контракта
dataset.py         загрузка и валидация фикстур
eval.py            живая оценка JEV на фикстурах
__main__.py        живая проверка одного сообщения
domain.py          типы данных, без I/O
```

## Контракт

`fixtures/contract/aag_tenders.json` — снимок списка «Тендеры» из ClickUp. Поле Billing разделяет задачи:
- `paid` (💰 Paid) — входит в контракт;
- `to_offer` (💡 To offer) — не входит, предлагаем отдельно.

Для каждой задачи хранятся краткое описание и фразы, которыми заказчик о ней пишет. Контракт целиком попадает в промпт. JEV возвращает `contract_item` — ID задачи в ClickUp, к которой относится сообщение. Если в ClickUp что-то поменялось, снимок нужно обновить.

## Фикстуры = «обучение»

`fixtures/classifier/*.json` — сообщения с правильными ответами на анкету: реальные из чатов (`aag_tendo_tp`, `ii_zastroyshik`) и синтетические, сочинённые по задачам контракта (`aag_contract_synthetic`). Работают в двух ролях:
- для LLM это **few-shot примеры**: к каждому запросу подмешиваются 8 самых похожих кейсов;
- для нас это **eval-набор**: по нему проверяем, насколько движок прав.

Чтобы научить модель новому случаю, добавьте в JSON кейс с правильными ответами. Формат при загрузке проверяется: неизвестный вопрос, недопустимая буква или пропущенный ответ дадут ошибку.

## Запуск

```bash
pip install -e '.[dev]'
export OPEN_ROUTER_KEY=...

python -m classifier "При выгрузке листов КП они становятся заблокированными"   # одно сообщение вживую
python -m classifier                                                            # интерактивно, по строке
python -m classifier.eval -v                                                    # все фикстуры: точность, цена, какие модели выбрал роутер
python -m classifier.eval --only ct-01,ct-26 -v                                 # выборочно

pytest   # офлайн-тесты, JEV подменяется моком
```

Переменные: `JEV_MODEL` (по умолчанию `typesafe/jev-router`), `JEV_REASONING_EFFORT` (`low` / `medium` / `high`; не задано — роутер решает сам), `JEV_TIMEOUT`.
